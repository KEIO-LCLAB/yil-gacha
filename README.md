# YIL COLLECTION GACHA

慶應義塾大学・矢上祭のYIL展示ブース向けガチャ。黄色×黒のデザイン、提供ロゴ、CSSカプセル、抽選演出、紙吹雪、電子音を搭載しています。外部ライブラリ・外部フォント不要。個人情報入力・在庫管理はありません。公開版は上限枚数をFirestoreから取得します。

## 起動

PCではフォルダーを展開し、index.htmlをブラウザで開くだけで動作します。assetsフォルダー、style.css、shared.js、app.jsは同じ配置のまま保管してください。

簡易サーバーを利用する場合、このフォルダーで次を実行します（Python 3が必要）。

```sh
python3 -m http.server 8000
```

同じPCでは http://localhost:8000 を開いてください。iPad・スマホでは、同じWi-FiのPCのIPアドレスを使って http://PCのIPアドレス:8000 にアクセスします。HTTPで開く場合は、管理者設定の取得にインターネット接続が必要です。iOSの「ファイル」アプリ内プレビューは通常のブラウザと異なるため、ブースではSafariと簡易サーバーの組み合わせを推奨します。端末単体でのローカルHTML実行は端末・閲覧アプリに依存します。

## 操作

1. 1〜11の数字ボタン、＋／−、または数字入力でカード枚数を選ぶ。
2. 当選率を確認し「ガチャをまわす」を押すか、ガチャ機のハンドルを右回りに約120度ドラッグ。キーボードではハンドルにフォーカスしてEnterでも抽選可能。
3. 出てきたカプセルをタップして開封する。開封するまで結果は表示されず、追加抽選はできません。
4. 結果をスタッフに見せて景品を受け取る。
5. 「もう一度」でカード1枚・確率0%に戻り、次の参加者へ。

音は常時ONで、ガチャ操作時に電子音が鳴ります。切替ボタンはありません。端末の音量・消音設定によっては聞こえない場合があります。抽選履歴・個人情報を保存しません。

## 確率仕様

景品はシールかクリアファイルのどちらか1つ。クリアファイル当選率は `Math.round(100 * ((cards - 1) / (maxCards - 1)) ** 1.7) / 100`（0〜1）。以下は上限11枚の場合です。後半ほど伸びるべき乗カーブです。シールはその補数。8枚で55%、11枚で100%。抽選・数値表示・カプセル表示は同じ式を使用します。

|カード|クリアファイル|シール|
|---|---|---|
|1枚|0%|100%|
|2枚|2%|98%|
|3枚|6%|94%|
|4枚|13%|87%|
|5枚|21%|79%|
|6枚|31%|69%|
|7枚|42%|58%|
|8枚|55%|45%|
|9枚|68%|32%|
|10枚|84%|16%|
|11枚|100%|0%|

カプセル10個で100%を表し、1個は10%分。端数は1個の上半分を黄色（クリアファイル）と白系（シール）で割合に応じて塗り分けます。例：55%なら黄色5個＋半分黄色1個＋白4個。カプセルは抽選結果の予告ではなく、確率の図解です。混ぜても内訳は変わりません。

クリアファイル当選者は希望によりシールへ変更可能。逆は不可。抽選開始時にMath.random()を1回だけ呼び、結果開封まで再抽選しません。

## 管理者確認

URL末尾に `?debug=1` を追加（例: http://localhost:8000/?debug=1）。画面下部に全確率・現在の状態・直近抽選の乱数と判定を表示。確率変更や強制当選機能はありません。通常は非表示です。

## アクセシビリティ

大きなタップ領域、数字への読み上げラベル、キーボード操作、フォーカス枠、結果ダイアログ内へのフォーカス移動を用意。OSで「視差効果を減らす」等を有効にすると、prefers-reduced-motionに従い動きを止め、抽選待ち時間を短縮します。

## 検証

Node.jsで `node tests/probability.test.cjs` を実行すると、上限2〜11枚の確率・境界値・景品の排他性・カプセルの割合を検証できます。
開催前に実際の使用端末で表示と音量をご確認ください。

## 管理者ページ

公開先は /admin.html。IDは yil。簡易ロック方式です。IDとパスワードからSHA-256キーを生成して管理用データへアクセスし、Firestoreルールで設定更新を制限します。パスワードそのものは公開ファイルに含めません。ブラウザ上でキーを生成する方式で、Firebase Authenticationのような認証・試行回数制限ではありません。管理キーを取得された場合は更新可能なので、ログイン情報を第三者へ共有しないでください。キーはメモリーのみ保持し、再読み込み・ログアウトで破棄します。

上限は2〜11枚。クリアファイル当選率は `round(100 * ((cards - 1) / (maxCards - 1)) ** 1.7)` %。1枚0%、設定した上限100%。上限1枚は両条件を満たせないため選択できません。数値・景品判定・10個のカプセルは共通の確率式に連動。

公開版は開始時・30秒ごと・画面復帰時・抽選直前に上限を取得します。抽選直前の上限取得に失敗した場合は抽選を止め、再確認を案内します。抽選中の変更は次の参加者に反映します。file://で開くオフライン版は上限11枚の独立運用です。管理者設定の共有にはインターネット接続が必要です。

## 設定ファイルと秘密情報

`firestore.rules` は管理キーを含むためGitの管理対象外です。`firestore.rules.example` は構造のみを示すテンプレートです。運用環境のルールファイルは管理者から別途安全に受け取り、テンプレートをそのままデプロイしないでください。ログインパスワード・管理キーはこのリポジトリに含めません。

既存サイトのHostingのみを更新する場合は、ログイン後に `npx firebase-tools deploy --only hosting` を使用します。Firestoreルールを変更する場合は実際の管理キーを設定したローカルファイルを使用し、`npx firebase-tools deploy --only firestore:rules` を実行します。別のFirebaseプロジェクトへ移す際には、`.firebaserc`・`firebase.json`・`shared.js`の接続先とFirestore初期データの準備が必要です。

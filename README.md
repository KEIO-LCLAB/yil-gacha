# YIL COLLECTION GACHA

慶應義塾大学・矢上祭のYIL展示ブース向けガチャWebアプリです。カードを集めた枚数に応じて、クリアファイルの当選確率が上がります。HTML・CSS・JavaScriptで動作し、外部ライブラリや個人情報の入力は不要です。

- **[ガチャを開く](https://keio-lclab.github.io/yil-gacha/)**
- **[運営用ページを開く](https://keio-lclab.github.io/yil-gacha/admin.html)** — スタッフの端末でブックマークしてください。

現在はGitHub Pagesで公開しています。旧Firebaseサイトは公開を停止し、旧設定データへのアクセスも閉じています。旧Firebaseプロジェクト `yil-gacha-ichii` も削除を申請し、`DELETE_REQUESTED`（削除待ち）を確認済みです。

## ブースでの使い方

1. 集めたカードの枚数を、数字ボタン・＋／−・数字入力で選びます。
2. 当選率を確認し、「ガチャをまわす」を押すか、ハンドルを右回りに回します。
3. 出てきたカプセルをタップして開封します。
4. 結果をスタッフに見せ、景品を受け取ります。
5. 「もう一度」を押して次の参加者へ進みます。

景品は**シールかクリアファイルのどちらか1つ**です。クリアファイル当選者は希望によりシールに変更できます。シールからクリアファイルへの変更はできません。

カプセルは10個で当選率を表します。枚数選択やカプセル部分のタップでかき混ぜられます。「ガチャをまわす」ボタンでは混ぜずに抽選します。抽選中・開封待ちは二重抽選を防止します。

## カード上限の変更

共通上限の初期値は**11枚**です。上限は2〜11枚で設定でき、設定した上限でクリアファイル当選率が100%になります。1枚では0%のため、上限1枚は選択できません。

|設定|変更方法|反映される範囲|
|---|---|---|
|共通設定|GitHubで `settings.json` を変更|端末別設定のないすべてのブラウザ|
|端末別設定|運営用ページの「この端末に保存」|操作したブラウザのみ。共通設定より優先|

### 全端末の共通設定を変更する

1. 運営用ページの「GitHubで共通の上限を変更」を開きます。
2. リポジトリへの書き込み権限があるGitHubアカウントでログインします。
3. `settings.json` の `maxCards` を2〜11の整数に変更します。例：上限8枚なら以下の内容です。

   ```json
   {"maxCards": 8}
   ```

4. 「Commit changes」で `main` ブランチに保存します。変更提案として保存した場合は、`main` への取り込みが必要です。
5. [Actions](https://github.com/KEIO-LCLAB/yil-gacha/actions)で「Publish GitHub Pages」が成功するのを待ちます。
6. ガチャ画面の「再確認」を押し、「共通設定：上限○枚」の表示を確認します。

公開処理が完了するまでは以前の設定が使われます。**端末別設定が残っているブラウザには共通設定が適用されません。**

### この端末だけ変更する

1. [運営用ページ](https://keio-lclab.github.io/yil-gacha/admin.html)を開きます。
2. 「この端末だけ変更」で上限を選び、確率表を確認します。
3. 「この端末に保存」を押します。
4. ガチャ画面へ戻り、「この端末：上限○枚（端末別設定）」を確認します。

設定はブラウザ内の `localStorage` に保存され、再読み込み後も残ります。同じ端末でも別のブラウザ・プロファイルには反映されません。ブラウザのデータ削除で設定は消えます。

共通設定へ戻すときは、運営用ページで**「共通設定に戻す」**を押してください。共通設定を取得できない場合は、解除せず通信確認を案内します。

### 運営用URLについて

運営用ページはパスワード不要です。通常のガチャ画面にはリンクを表示しません。URLを知る人は利用できますが、ここで直接変更できるのはそのブラウザの設定だけです。秘密のページや認証機能ではありません。全端末の共通設定はGitHubの書き込み権限で保護されます。

### 設定が反映されるタイミング

開始時・30秒ごと・画面復帰時・抽選直前に設定を確認します。抽選直前に上限が変わった場合は、新しい確率を確認してもう一度操作します。抽選済み・開封待ちの結果は変更しません。

共通設定を取得できない場合は抽選を停止します。通信を確認して「再確認」を押してください。端末別設定がある場合、その設定の取得に通信は不要ですが、公開サイト自体を新しく開くには通信が必要です。

## 当選確率

```text
クリアファイル当選率（%） = round(100 × ((カード枚数 − 1) / (上限 − 1)) ^ 1.7)
シール当選率（%） = 100 − クリアファイル当選率
```

後半ほど当選率が伸びる曲線です。数値表示・景品判定・カプセル表示は共通の確率計算を使用します。抽選では `Math.random()` を1回使います。

上限11枚の場合：

|カード枚数|クリアファイル|シール|
|---|---|---|
|1|0%|100%|
|2|2%|98%|
|3|6%|94%|
|4|13%|87%|
|5|21%|79%|
|6|31%|69%|
|7|42%|58%|
|8|55%|45%|
|9|68%|32%|
|10|84%|16%|
|11|100%|0%|

カプセル1個は10%分です。端数は色を分けて表現します。例えば55%は黄色5個分＋半個分です。カプセルは確率の図解であり、抽選結果の予告ではありません。

## ローカルで起動する

ファイル一式をダウンロードし、`index.html` をブラウザで開けます。`file://` では共通上限は11枚固定となり、`settings.json` は読み込みません。端末別設定の保存可否はブラウザに依存します。

共通設定も含めて確認する場合は、プロジェクトフォルダーで簡易HTTPサーバーを起動します（Python 3が必要）。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開きます。ローカルで保存した端末別設定と、公開サイトの端末別設定は別管理です。

## 更新・公開と検証

`main` へのpushでGitHub Actionsがテスト、ビルド、GitHub Pagesへの公開を実行します。Firebaseへの接続やデプロイは不要です。

```sh
node tests/probability.test.cjs
node tests/settings.test.cjs
node build.cjs
```

Node.jsで実行できます。確率テストは上限2〜11枚の境界値・景品の排他性・カプセルの割合を、設定テストは共通設定・端末別設定の優先順位・解除・読み込み失敗・入力制限を検証します。`build.cjs` は公開対象のファイルだけを `public/` に出力します。

|ファイル|役割|
|---|---|
|`index.html` / `style.css` / `app.js`|ガチャ画面・演出・抽選|
|`shared.js`|確率計算・共通設定取得・端末別設定保存|
|`settings.json`|全端末の共通上限|
|`admin.html` / `admin.css` / `admin.js`|運営用ページ|
|`assets/logo.png`|YILロゴ|
|`.github/workflows/pages.yml`|テストと自動公開|

URLに `?debug=1` を付けると確率・抽選状態を確認できます。音は操作後に鳴り、端末の音量設定に従います。OSの `prefers-reduced-motion` に合わせて動きを抑えます。開催前には実際に使用する端末で表示・設定・音量を確認してください。
